## Reflexão
### Qual foi a principal vantagem de utilizar branches?
A vantagem se dá integralmente pela possibilidade de múltiplos desenvolvedores trabalharem em *features* diferentes, e posteriormente enviar essas alterações para uma única branch, separando e unificando o progresso do projeto quando conveniente.

### Por que os Pull Requests são importantes em projetos colaborativos?
Para evitar que commits descuidados ocorram, pois possibilita que outros devs possam revisar e aprovar as alterações, além de possibilitar a separação de papéis, como QA (Quality Assurance).

### Como acontece um conflito de merge?
Ocorre quando há muitas alterações "brutas" no mesmo arquivo - dependendo da complexidade, o próprio github consegue fazer o merge automaticamente sem atuação manual, mas em casos de conflito, é necessário que um dev decida qual código irá sobrescrever as seções conflitantes.

### Como a equipe resolveu o conflito encontrado?
Abrimos as seções conflitantes no código, utilizando o Github de navegador. Havia um conflito no style.css, pois ambos desenvolvedores escreveram código diferente no mesmo arquivo.

### Qual prática de GitHub a equipe considera mais importante em projetos maiores?
Separação de papéis, e principalmente a questão de pull requests controlados, projetos maiores tendem a ter mais desenvolvedores com níveis de habilidade diferentes, assim tendo mais chance de ocorrer erros de atenção, e conflitos em *merges*.
